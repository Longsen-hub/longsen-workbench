# 五维岗位匹配评估（Job Evaluation）

评估一个岗位值不值得投、匹配度有多高。**门禁先行，评分在后**：硬门槛门禁是二元的（FAIL 硬停），五维评分是连续的（0-100）。两者永不混淆。

---

## 一、硬门槛门禁（评分前必跑）

逐条读取 JD 的硬性要求原文，对照候选人画像分类。**门禁只看 JD 明确写死的硬条件，不看"优先/加分"项。**

| JD 表述 | 判定 |
|---------|------|
| 学历硬性要求（"统招本科及以上""必须硕士"等） | 不达标 → **FAIL 硬停** |
| 年限硬线（"3 年以上经验"且无"或同等能力"字样） | 不达标 → **FAIL 硬停** |
| 证书/资质必需（注册类、执业资格、特定认证） | 缺失 → **FAIL 硬停** |
| 行业/背景门槛（金融从业、政企保密、军工、国企政治面貌要求、背调硬性项） | 不达标 → **FAIL 硬停** |
| 语言硬性要求（"英语为工作语言""英语口语流利""粤语流利"作为岗位条件） | 不达标 → **FAIL 硬停** |
| JD 写"优先""加分""有 X 更好" | **不是门禁**，降级为评分维度中的加分项 |
| JD 完全未提及某类条件 | 继续，但标注"未验证" |

### FAIL 硬停规则

1. 命中任何一项 → **不评分、不起草、不进入后续任何流程**。
2. 把 JD 原文原句引用回给用户（一字不改），说明差距在哪，让用户决策。
3. 用户可能掌握简历之外的真实情况（如自考本科但有统招硕士、有内部推荐豁免），由用户判断是否继续。
4. 报告失败时引用出处，不要静默放弃。

### 两条容易搞错的规则

1. **沉默不等于放行**：JD 没写学历要求，不代表没门槛——大型企业、国企、政企项目常在官网或后续流程卡学历。评分后可在公司调研中补充验证。
2. **"公司欢迎人才"不等于"该岗位无门槛"**：公司层面欢迎 vs 岗位层面硬性要求是两回事，以岗位 JD 原文为准。

### 中国求职场景补充（本土化）

- 学历表述常见差异：统招本科 / 专升本 / 自考 / 成教 / 非全日制硕士——JD 写"统招"时，非统招学历按 FAIL 处理，除非用户确认实际简历可过
- 年限常写"3-5 年""5-10 年"区间：按区间下限判断，下限不达标才 FAIL
- 证书类：软考（软考高级/中级）、PMP、CPA、CFA、教师资格证、执业医师等，JD 明确"必需"才算门禁
- 背景门槛：涉密岗位（保密资格）、金融从业资格、国企党员要求、政企项目的背调
- 语言：外企"英语作为工作语言"、大湾区"粤语流利"、对日外包"日语 N2/N1"

## 二、五维评分

### 维度 1: 技术技能匹配（0-100）

JD 的 required/preferred 技能与候选人能力的对齐程度。

| 分数 | 含义 |
|------|------|
| 80-100 | 核心技术要求就是候选人的主力技能 |
| 60-79 | 大部分匹配，1-2 个可学习的缺口 |
| 40-59 | 部分匹配，需要显著补强 |
| 0-39 | 根本性错配 |

记录：强匹配区（主力技能）/ 中等匹配区（次技能）/ 弱匹配区（缺失技能）。

### 维度 2: 经验匹配（0-100）

工作经历与岗位领域、角色类型的直接程度。

| 分数 | 含义 |
|------|------|
| 80-100 | 同领域同角色直接经验 |
| 60-79 | 相关经验，迁移能力清晰 |
| 40-59 | 相邻经验，需要论证 |
| 0-39 | 无关经验 |

注意「长年限低产出」问题：一段两年经历只展示一个项目，读起来像低产出。三种诚实修法（按优先级）：
1. **挖更多真实工作**：期间的真实副项目、内部工具、支持性工作，即使当时觉得"太小"
2. **把角色内阶段写明**：先期学习/支持，后期独立交付——分段弧线读起来是成长曲线，整块多年读起来是停滞
3. **说明长周期原因**：数据采集周期、专家验证、部署迭代

**绝不**用伪造项目填充，**绝不**悄悄缩短日期让比例好看。两者都会被识破，且比要解决的问题更糟。若修完仍显低产出，把"那段时间实际做了什么 + 结果如何"的两段式答案写进面试准备，而不是在简历里硬撑。

### 维度 3: 行为文化契合（0-100）

角色与团队/公司文化与候选人行为偏好的契合度。

| 分数 | 含义 |
|------|------|
| 80-100 | 文化强匹配行为偏好 |
| 60-79 | 信号混杂但大体兼容 |
| 40-59 | 存在摩擦点 |
| 0-39 | 显著不匹配 |

调研来源（中国场景本土化）：看准网、脉脉、知乎、公司官网、媒体报道、牛客；外包驻场文化、加班文化（大小周/996）、OKR/绩效文化、领导风格。**调研结论必须来自真实抓取的页面，搜索摘要只是线索不是证据。**

### 维度 4: 地点后勤（PASS/FAIL + 备注）

- 通勤范围内：PASS
- 远程/偶尔到岗：PASS
- 需搬迁：FAIL（除非用户明确接受）
- 频繁出差：FLAG（与用户讨论）
- 中国场景补充：一线/新一线生活成本、户口/居住证影响、公积金与社保基数、到岗时间要求（"尽快到岗" vs 一个月后）

### 维度 5: 职业动机（0-100）

该角色是否推进职业目标、任务是否让人有能量。

| 分数 | 含义 |
|------|------|
| 80-100 | 与职业方向强一致，有清晰成长路径 |
| 60-79 | 好岗位但部分偏离长期目标 |
| 40-59 | 还行但不积累 |
| 0-39 | 死胡同或倒退 |

动机过滤：不仅看能不能做，还要看是否被任务点燃。记录：让你有能量的任务 / 消耗你的任务 / 非任务因素（领导风格、团队文化、公司价值观、自主度）。生活约束：薪资需求、作息约束、成长优先级。

---

## 三、加权与总分

- 技术 30% + 经验 25% + 行为 15% + 动机 30%（地点不计权）
- 总分 = 四维加权和
- 地点 FAIL：整体 FAIL，除非用户明确接受搬迁/出差条件
- 加权明细写在评估表里，让用户能复算

## 四、判定阈值

| 判定 | 总分 | 行动 |
|------|------|------|
| **Strong** | ≥75 | 值得投，全面定制 |
| **Good** | 60-74 | 投，在求职信/沟通中说明缺口 |
| **Moderate** | 45-59 | 谨慎，与用户讨论后再投 |
| **Weak** | 30-44 | 除非有战略理由否则跳过 |
| **Poor** | <30 | 跳过 |

**经验匹配 <50 时**：起草前必须警告用户"该岗位需要大量改写来论证匹配度，存在过度改写风险"，询问是否继续。

## 五、输出格式

```markdown
## 岗位匹配评估：[岗位] at [公司]

| 维度 | 分数 | 备注 |
|------|------|------|
| 技术技能 | XX/100 | [简述] |
| 经验匹配 | XX/100 | [简述] |
| 行为文化 | XX/100 | [简述] |
| 地点后勤 | PASS/FAIL | [简述] |
| 职业动机 | XX/100 | [简述] |

**总分：XX/100**（加权明细：技术30%×XX + 经验25%×XX + 行为15%×XX + 动机30%×XX）

### 判定：Strong / Good / Moderate / Weak / Poor

### 核心优势
- [bullet]

### 待补缺口
- [bullet]

### 建议
[1-2 句：投 / 不投 / 有条件地投]

### 公司调研清单
- [ ] 官网（使命、价值观、近期动态）
- [ ] 看准网/脉脉/知乎评价
- [ ] 脉脉/领英查团队规模与近期招聘
- [ ] 媒体报道（扩张/收缩/组织变动）
- [ ] 确认无内部人脉可问（有则记下）
```

## 六、投递决策辅助

- **面试回溯测试**：任何改写后的表述，候选人能否在面试中不翻车解释？"其实我想说的是…" = 过度改写，回退。
- **需求覆盖核对**：JD 每个 stated requirement 都要被处理——匹配或诚实标缺口，绝不沉默遗漏。缺口用桥接表述（"不是日常主力工具，但是 X 的自然延伸"）。
- **用 JD 原文术语**：ATS 和快速扫读的 HR 按字面匹配，"MLOps" 标题比"模型部署"这类同义改写命中率高。仅当真实适用时才用原文术语，禁止为匹配而堆砌。
