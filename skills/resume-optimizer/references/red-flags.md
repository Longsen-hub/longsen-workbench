# 常见问题与红旗

## 1. 外包经历处理

以下类型的经历容易引发面试官追问：

### 大型 IT 服务/外包

- 中科软
- 中软国际
- 法本信息
- 软通动力
- 东软集团
- 文思海辉
- 博彦科技
- 柯莱特

### OD / 驻场 / 外包性质

- 华为 OD
- 阿里外包
- 字节外包
- 腾讯外包

处理原则：

- 外包经历本身不是原罪
- 真正的问题是项目价值、职责边界和成长路径没讲清楚
- 如果做过核心项目，重点写项目，不要把公司标签放大
- 如果有从外包走向甲方、平台型团队或更核心业务的路径，这是正向信号，应该主动表达

## 2. 致命问题

这些问题会显著降低面试机会：

- 时间线冲突
- 技术栈前后矛盾
- 明显夸大头衔或数据
- 错别字、术语错误、语病很多

## 3. 高风险问题

- 频繁跳槽但没有解释
- 一堆“精通”却找不到项目证据
- 所有描述都停留在职责层
- 用玩具项目填充真实经验不足

## 4. 常见低级问题

- 个人摘要太长
- 自我评价空洞
- 几乎没有量化信息
- 日期格式、项目格式不统一

## 5. 玩具项目识别

这些项目如果写法普通，很难加分：

- 外卖系统
- 秒杀系统
- 商城系统
- 博客系统
- 在线教育平台

风险不在于项目题材本身，而在于：

- 没有真实场景
- 没有独特取舍
- 没有复杂问题
- 没有结果证明

如果必须保留，至少要突出一项真实亮点：

- 压测和容量设计
- 限流、缓存、一致性等关键技术细节
- 为什么选这个方案
- 做完之后带来的结果

## 6. 空窗期与断层

常见情况包括：

- 创业失败
- 读研或进修
- Gap period
- 裁员
- 身体或家庭原因

处理建议：

- 可以简短解释，但不要长篇自辩
- 重点放在这段时间学到了什么、积累了什么
- 如果有持续学习、项目实践或证书补充，尽量放上去
